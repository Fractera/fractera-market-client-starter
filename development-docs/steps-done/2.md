# Step 2 — The recommendation list with the history of choices (done 2026-11-27)

Serves: S-01, R-01, R-03, R-04, E-01, E-02, E-03
Stage: 0

**What.** Stage 0 of the quiz against the store stub: an element asks for a recommendation, rows appear in the list, the person's
choices become the task's history and go out with every next search.

**How.**
- `lib/market/store.mjs` — `search(envelope)` in the store's search v2 standard (given by the core's main agent 2026-11-27, substep 2-1
  dropped). Today a stub: two test starters `fractera-test-post-starter` «Тестовый пост» and `fractera-test-image-starter`
  «Тестовая картинка», price 0, `mode: "stub"`, its `summary` says how much history it received. Later only its body calls the
  core's store door (862-2).
- `lib/market/repo.mjs` — tables `market_recommendations`, `market_cart`, `market_history` (one entry per task + starter) in this
  element's own space of the data element (`/db/migrate`, `storeHeaders`); a memory backend for the tests.
- `lib/market/market.mjs` — the work of the doors; five doors by `npm run door:add`: `POST /api/recommend`, `GET /api/recommendations`,
  `POST /api/choice`, `POST|GET /api/cart`, `GET /api/history`; the A2A card filled with real samples, `accepts` and `returns` written.
- Decisions taken as defaults (open in the quiz until the architect confirms): Q-01 — at most 10 active rows per task, the oldest
  waiting/kept rows move to the history as «kept»; Q-02 — the Telegram summary comes with stage 2. A row is «waiting» before the
  person's decision; deleted → history «rejected», kept or cart → «kept». A neighbour (its own key) gets only its own rows and 403 on
  choice and cart — those are the person's acts. A line leaving the cart turns its row back to «kept».
